Approve Claude Code's risky commands remotely

Let the agent keep working while a git push waits for you, then approve it from claude.ai/code over Remote Control, whenever you look.

Tested on 2026-10-28 with Claude Code 2.1.287 on macOS, approving from claude.ai/code in a desktop browser. Not yet tried from a phone.

Short version: turn on Claude Code's Remote Control, let the free Agent Mission Control plugin hold risky commands, and send /mc approve a1 from claude.ai/code. The command runs exactly as it was held, once.

Why not just answer the permission prompt?

Remote Control already forwards permission prompts, to claude.ai and the Claude app, and that's great when you're nearby. Overnight it has two gaps:

  • A prompt blocks the whole run. If the agent asks at 1:52 and you answer at 7:40, it did nothing for six hours.
  • Some modes don't ask. In auto mode, a push to the repo you're working in runs without a prompt, and with skip-permissions a push runs without asking unless you've added an ask rule for it.

A hold is different. A PreToolUse hook fires before Claude Code's permission check, in every permission mode, so the plugin can stop the command, queue it as a1, and tell the agent to carry on with other work. You decide later.

Set it up

  1. Install the plugin

    From the Claude Code prompt, one line at a time:

    /plugin marketplace add long-run-labs/agent-mission-control
/plugin install agent-mission-control@long-run-labs

    It's free and MIT, has no dependencies and makes no network connections. It does nothing in a project until you give it a goal there.

  2. Turn on Remote Control

    Start the session with claude --remote-control, or run /remote-control in a session that's already running. The session then shows up at claude.ai/code and in the Claude app. Remote Control needs a claude.ai Pro, Max, Team or Enterprise login, not an API key, and on Team or Enterprise an Owner has to turn it on first. For pushes to your phone, install the Claude app, sign in to the same account, allow notifications, and in /config turn on Push when actions required and Push when Claude decides. See Anthropic's Remote Control docs.

  3. Give it a goal and a budget for the night

    /mc goal Migrate the API tests to Vitest --done-when npm test passes
/mc set maxToolCalls 2000
/mc set maxMinutes 900

    The minute budget counts from when you set the goal, including the hours a held command waits for you, so give it room for the morning. If it runs out before you approve, send /mc reset-budget first.

    Held by default: git push, npm publish, rm -rf, rm -fr, git clean with x, terraform apply, kubectl delete, curl … | sh, curl … | bash and wget … | sh. /mc set requireApproval replaces that list, so include the defaults you want to keep. Inside a pattern, * matches any text, as in git*push.

What a night looks like

23:04you/mc goal Migrate the API tests to Vitest
01:52hold a1git push origin vitest-migration
01:53agenta1 is held, so I'll keep going with tests/billing.
05:55agentnpm test passes. Waiting on a1.
07:40claude.ai/mc approve a1
07:40goRan exactly what you approved.

An illustration. When the agent has nothing left to do but the held command, it stops and says it's waiting on a1. Open the session at claude.ai/code, type /mc approve a1 (or /mc deny a1 not before the release) and send it. The approval starts a new turn, so the agent picks up by itself and runs the command.

What we tested, exactly

We used a throwaway repo and an interactive Claude Code session with the plugin and Remote Control on. We asked the agent to push; the push was held as a1 and the run stopped to wait for it. From claude.ai/code in a desktop browser we sent /mc approve a1. The plugin logged "a1 approved", the agent ran git push, and the commit reached the remote.

Two things to know:

  • The web composer says "/mc isn't a command here". Send it anyway: the message still reaches your session, and the session applies it.
  • We haven't tried it from a phone yet, in the Claude app or a phone browser. The app may treat unknown commands differently, so we won't claim it until we've seen it. We'll update this page when we have.

Will I get a notification when something is held?

Not reliably. Remote Control sends a push for permission prompts and questions, and a hold is neither: the agent just keeps working. Push when Claude decides lets the agent send a notification when it thinks you should know, which may or may not happen at a hold. If you want an alert every time, the paid kit sends one through ntfy when a command is held, the agent is blocked, or the run finishes.

Limits

LimitWhat it means
Your machine stays onRemote Control drives a session running on your computer, so it has to stay awake and online.
Subscription loginRemote Control needs a claude.ai login. With an API key, approve at the machine; the kit's ntfy alert tells you when.
Patterns are a seatbeltHolds match the command text. An agent that deliberately disguises a command can get past them, so keep Claude Code's own permissions on.
Only a person's /mc countsThe plugin applies /mc typed by a person in an attended session, including over Remote Control, and refuses the usual ways an agent could approve itself. Like the patterns, that's a seatbelt, not a sandbox.
