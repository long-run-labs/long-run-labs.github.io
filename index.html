The problem

Long runs fail in two ways

It stops too early

A quiet stop halfway through a migration while you were asleep, with nobody to tell it to keep going.

It doesn't stop when it should

A force-push, a publish or an rm -rf it should have asked about, or three hours burned on a dead end.

What it does

A human in the loop, without a human at the keyboard

HOLD

Risky commands wait for your GO

git push, npm publish, rm -rf or your own patterns are held as a1, a2… The agent keeps working on other things. /mc approve a1 runs exactly that command, once.

BUDGET

Budgets that actually stop it

Cap tool calls, minutes and automatic continues. When one runs out, every tool is refused and the agent is told to wrap up.

STEER

Steer from the chat

/mc say use the staging DB, /mc answer q1 Postgres, /mc status. No restart, no lost context.

GOAL

A finish line it can't loop on

Set a goal and a "done when". It keeps going until the agent marks it done, and lets the run stop when it's waiting on you, out of budget, or stuck.

LOCKED

It doesn't approve itself

Your commands are refused when the agent tries them, through mc or by sending /mc another way, and starting a nested claude waits for your GO. If the state can't be read, tools are refused rather than the checks switching off.

LOCAL

The plugin sends nothing

One JSON file per project, git-ignored. No network connections, no telemetry, no account.

Under the hood

One hook on seven Claude Code events

No daemon, no service: Claude Code calls one small Node.js script at these points, and it reads and writes one file.

EventWhat Mission Control does
SessionStartGives the agent the mission brief: goal, budget, open questions, recent log, how to report
UserPromptExpansionApplies the /mc commands you type
UserPromptSubmitPasses along anything new from you
PreToolUseRefuses tools on hold or out of budget; holds commands that need a GO; keeps the agent out of its own state

StopWhile a goal is active, keeps going until it's done, unless it's waiting on you, out of budget, or stuck

Install

Running in a minute

1. The free plugin, from the Claude Code prompt. It does nothing in a project until you give it a goal there.

/plugin marketplace add long-run-labs/agent-mission-control
/plugin install agent-mission-control@long-run-labs

2. In your project, give it a goal and, for a long run, the budget for it:

/mc goal Ship the CSV export --done-when tests pass and a PR is open
/mc set maxMinutes 600
/mc set maxToolCalls 2000

The kit, from the folder you unzipped. In that project, the kit's copy takes over from the plugin.

node install.mjs /path/to/your/project
cd /path/to/your/project && node .mission/cli/mc.mjs ui   # prints the console's private link

Needs Claude Code and Node.js 18.17 or newer on your PATH. Tested on macOS; Linux and Windows aren't tested yet.

FAQ

Questions

Why not just Claude Code's /goal?

/goal keeps a run going until a condition holds, and that's the part of long runs it covers. Mission Control has its own finish line, and adds what /goal doesn't: commands that wait for your GO while the agent keeps working, budgets that refuse tools once they're spent, and notes and answers you send mid-run.

Does it send my code or prompts anywhere?

No. The free plugin makes no network connections at all. The kit runs on your machine too. Its one exception is phone alerts, which are optional: each one carries the command waiting for approval, or the agent's question or summary, to ntfy.sh (topics are readable by anyone who guesses the name) or to your own ntfy server. Details are in the privacy policy.

Can the agent approve its own commands?

Not by any ordinary route. Your commands, like approve, resume and reset-budget, are refused when the agent tries them, and so is anything chained onto mc or touching its state folder. A /mc only counts when a person types it in a session they're attending: one sent through a nested claude -p, a scheduled prompt or a script is refused, and starting any nested claude waits for your GO. Like the approval patterns, which match command text, this is a seatbelt, not a sandbox: an agent that deliberately disguises a command can get past it. The skill tells it not to, and Claude Code's own permissions still apply.

What happens when the agent stops?

When it's waiting on you (a held command or a blocking question), type /mc approve a1 or /mc answer q1 … in its session and it carries on. If you answer in the console or a terminal instead, type continue in its session afterwards, or run claude -p --continue for headless runs.

Can I steer while it's working?

Yes, with one catch. A /mc you type while the agent is working waits until the run stops, so press Esc first to send it right away. Esc stops the current step, and the agent picks up again after your /mc. Or run mc say … in a terminal: the note reaches the agent at its next tool call, without interrupting it.

Can I approve from my phone?

Not yet. With the kit, your phone gets the alert, and you approve at your machine, with /mc in the chat or in the console. The console is local-only on purpose.

Does it work with my team's settings?

The plugin is installed per person and keeps each project's state in a git-ignored .mission/ folder. The kit's installer writes to your own .claude/settings.local.json by default; use --shared to put the hook in the committed settings for the whole team.

Linux and Windows?

It's plain Node.js with no dependencies, and the hook is written to work under Git Bash and PowerShell, but so far it's only been tested on macOS. If you try it elsewhere, an issue with what you saw helps a lot.

How do I get help?

Open an issue on the GitHub repo. For anything about a purchase, open one titled "Purchase", with no personal details, and we'll reply there with a private way to reach us.
