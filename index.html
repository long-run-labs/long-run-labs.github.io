What it does while you sleep

A human in the loop, without a human at the keyboard

Long runs fail in two ways: they stop too early, or they don't stop when they should. Four small mechanisms cover both.

HOLD

Risky commands wait. The run doesn't.

git push, npm publish, rm -rf or any pattern you add is held as a1, a2… The agent is told it's queued and gets on with other work. /mc approve a1 runs exactly that command, once, even when you send it remotely through Remote Control.

git pushnpm publishrm -rfterraform applyprisma migrateyour pattern *
agentgit push --force origin main
holda1 queued · waiting for your GO
agenta1 is held. Moving on to the docs.
BUDGET

A budget it can't talk its way past.

Cap tool calls, minutes and automatic continues. When tool calls or minutes run out, every tool call is refused and the agent is told to wrap up; when continues run out, the run is allowed to stop. A new goal starts a fresh budget.

FINISH LINE

A finish line, not a loop.

Give it a goal and a "done when". It keeps working until the agent marks the goal done, and stops on its own when it's waiting on you, out of budget, or stuck.

stop?Not done yet. Keep going (continue 3 of 25).
stop?Waiting on a1. Stop and leave it for you.
stop?No tool calls since the last automatic continue. Stuck, so stop.
STEER

Steer it without starting over.

Send a note, answer its question, or check what it's doing, with /mc in the same chat. No restart, no lost context. Or send a note from another terminal and it arrives after the agent's next tool call.

you/mc say keep the old endpoint working until v3
agentNoted. Keeping /v2/export and adding a deprecation header.
you/mc status

FAQ

Questions

How is this different from permission prompts?

A permission prompt asks right away and waits. That's right when you're at the keyboard. Overnight, it stops the whole run until morning, and in auto or skip-permissions mode a push to your repo doesn't ask at all. A hold queues just that command as a1, tells the agent to carry on with other work, and runs exactly what you approved, once. Claude Code's own permissions still apply on top.

Why not just Claude Code's /goal?

/goal keeps a run going until a condition holds. Mission Control has its own finish line, so you don't need both, and adds what /goal doesn't: holds that don't block the run, budgets that refuse tools once they're spent, and notes and answers mid-run.

Does it send my code or prompts anywhere?

No. The free plugin makes no network connections at all. Details are in the privacy policy.

Can the agent approve its own commands?

Not by any ordinary route. Your commands, like approve, resume and reset-budget, are refused when the agent tries them, and so is anything chained onto mc or touching its state. A /mc only counts when a person types it in a session they're attending: one sent through a nested claude -p, a scheduled prompt or a script is refused, and starting any nested claude waits for your GO. It's a seatbelt, not a sandbox: an agent that deliberately disguises a command can get past pattern matching, and a Claude Code mod you install can override a hold, so Claude Code's own permissions still matter.

Can I steer while it's working?

Yes. A /mc typed while the agent is mid-step waits until that step ends, so press Esc first to send it right away; the agent picks up again after your /mc. Or run mc say … in another terminal, and the note reaches the agent after its next tool call without interrupting it.

Can I approve when I'm away from the machine?

Yes, with Claude Code's Remote Control. Turn it on for the session, then send /mc approve a1 from claude.ai/code. We tested this in a desktop browser: the web composer says "/mc isn't a command here", but the message still reaches your session and the held command runs. We haven't tried it from a phone yet. Remote Control needs a claude.ai subscription login, not an API key. Step-by-step guide.

Linux and Windows?

It's plain Node.js 18.17+ with no dependencies, but so far it's only been tested on macOS. If you try it elsewhere, an issue with what you saw helps a lot.
